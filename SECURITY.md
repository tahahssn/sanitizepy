# Security Policy

### *sanitizepy handles your data. If something's wrong with how it does that, we want to know.*

</div>

## Supported Versions

Security patches are applied to the latest release only.

| Version | Supported |
|---|---|
| `0.1.x` | ✅ Active |
| `< 0.1` | ❌ End of life |

## Reporting a Vulnerability

**Do not open a public GitHub issue for security vulnerabilities.**

If you discover a security issue within `sanitizepy`, report it privately by emailing the project maintainer directly via GitHub. Navigate to [tahahssn's profile](https://github.com/tahahssn) to find contact options, or use GitHub's [private vulnerability reporting](https://github.com/tahahssn/sanitizepy/security/advisories/new) feature if available on your account.

Include the following in your report:

- A clear description of the vulnerability
- Steps to reproduce the issue
- The version of `sanitizepy` affected
- Any proof-of-concept or example code if applicable

## Response Timeline

| Stage | Target |
|---|---|
| **Acknowledgement** | Within 48 hours |
| **Initial assessment** | Within 5 business days |
| **Patch release** | Dependent on severity |

Critical vulnerabilities are prioritised and patched as quickly as possible. You will be credited in the release notes unless you prefer to remain anonymous.

## Scope

This policy covers the `sanitizepy` library itself. Vulnerabilities in third-party dependencies (`pandas`, `numpy`, `scipy`, `rich`, `pydantic`) should be reported to those projects directly.
